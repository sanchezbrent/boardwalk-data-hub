# Delivery increments and acceptance

The first public project is the editor; its first development increment is an
explicitly bounded electricity pilot. The broader contract serves future plugins.

| Increment                               | Acceptance boundary                                                                                                                                     | Current state                                                   |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Repository governance and private pilot | Versioned contract; strict source profile; author/validator/approver separation; digest/CAS checks; local UI and CI/configuration                       | Implemented locally; hosted status comes from bootstrap receipt |
| Generic Boardwalk host                  | Static installation policy; lazy route; explicit grants; authenticated gateway; real transactional private persistence, retention and audit; deny rules | Proposed, with type-checked wrapper and server port             |
| Electricity reader adapter              | Data-driven public and responsive preview renderer, captions, no-script and every export; complete before/after/golden parity                           | Not implemented                                                 |
| Atomic Hub publication                  | Exact revision approval, all latest outputs in one complete accepted manifest; predecessor CAS; failure/retry/recovery proofs; pinned immutable bytes   | Not implemented                                                 |
| Remaining 17 profiles                   | Strict schemas for actual source shapes; no data loss; independent calculations and metadata/rights review; visual/export parity                        | Inventory only; no permissive fallback                          |
| Second real plugin                      | Use the same installation/grant/lifecycle protocol; prove disable and compatibility behavior; then extract shared API                                   | Next architectural validation                                   |

Every figure requires a named editorial update owner and backup, source release
cadence, next review date, original source/series/vintage/methodology, geographic
scope, observation status and independently reviewed reuse evidence. Unknown or
denied reuse may remain private but cannot pass review. Same-series comparisons
cannot be overridden with prose. WARN, energy-employment and fiscal-accounting
additions require separate source/methodology proposals after the existing figures.

Before activation, test default-off and revoked access, direct storage denial,
concurrent edits, author/validator/approver separation, changed payloads and grants,
unknown rights, private-evidence leakage, unsafe text and export formula injection,
all 18 responsive figures, complete artifact preparation failures, pointer races,
retries using the original operation, rollback and pinned bytes across code upgrades.
A green source suite, an approval record or a matching snapshot is not live proof.

The local transition is a pure review core. expectedVersion refuses stale writes;
it is not a durable idempotency receipt. Production needs durable operation IDs,
request fingerprints and retained outcomes before publication retries can be safe.
History and retention are required by the host transaction port, not magically
provided by the memory demo. Scope and ownership must be checked by the real host.
